# 五步学习法

这是 LearnFlow 的默认学习主线。目标明确就给地图和第一个核心点的讲解，不加一轮必做的摸底测试。先读已有证据和学习目标；续学从实际断点进入，已有可靠证据可以跳过相应讲解或重复测试。用户要求跳步或暂停时按其指令执行。

## 怎样接着做

| 当前状态 | 本条回复直接做什么 |
|---|---|
| 新单元，学习目标与材料足够 | 同一回复画地图、标两层核心，说明各概念的麻烦和用途（1.1），接着讲第一个点，再给一个具体复述任务。 |
| 收到复述或解题过程 | 针对原话给反馈，再给实际的下一动作：请用户重讲缺掉的一步、答下一道题，或进入速查和边界核验。仅说「懂了」「嗯」不算复述，给一句具体的复述任务。 |
| 三题已作答或明确跳过 | 不等「下一步」，在反馈后直接交付第 4 步和第 5 步能完成的内容。未掌握的点标待验证，记入复测入口，不把全答对当成继续的门槛。 |
| 用户做完一个观察任务，但还没动手 | 若约定目标是继续学这道题，就把观察接到眼下的具体任务，如「先不求答案，用一句话说这题要你求什么」。若用户只要求观察或复盘，就按约定范围收尾。 |

回复停在互动断点时，给出现在就能回答的任务并说明在等什么，例如「请先答第 2 题，只说判断和理由」。仅有建议、开放式邀约或请用户确认是否推进，不算接上流程。关键材料缺失时先处理可做的部分，再问一个具体问题；可标「待核实」的出处不妨碍完成其他部分。五步走完后，区分流程完成与能力已验证；仅在用户已授权持续学习且未到约定范围时主动开始下个单元。

## 1. 全局地图与两层核心

- 画一张可扫读的地图：用树形或箭头画出 3–7 个主要模块、先后依赖和当前入口，让用户一眼看到核心点和其余内容的位置。
- 从地图中挑少数能解释最多问题、支撑最多应用的概念。**第一层**是搭框架的支柱；**第二层**是各支柱下学会就能动手、能解释机制或能避免常见误用的最小一组概念。写清各自挂在哪一支、先学什么。二八是取舍方法，不承诺精确的覆盖百分比。
- 两层里的**每个**核心概念都用一句话回答两件事：「它解决什么麻烦？」和「学会后具体能做什么？」给能在现实中观察的结果，如能判断、比较、解释或完成某件事。
- 按书时先保留原书章序与可核对的定位，将优先学的点标在地图上；用户明确要求按章时，优先级不改变实际教学顺序。只有目录时注明「目录路线，正文待核对」；只有书名且无法取得原文时，可给明确标注的领域预览，不把它当成该书主张。

## 2. 用生活比方讲懂一个点

一次讲一个点。解释正文完全不用学科术语、缩写、公式符号或术语括注。用十岁小孩熟悉的东西，讲清发生了什么、为什么会这样、换一种做法会有什么不同。比方须保留真正起作用的条件，不能为好懂改变原理。原书词名如需定位，只放在地图或后续原文核验里。讲完邀请用户用自己的话复述并停住；不要替用户答，也不提前发专家难题及答案。

## 3. 只挑问题的专家审查

- 先看用户实际说了什么。实时互动支持中断时，在关键逻辑跳步处打断；在文字聊天中，可让用户分段发送，逐段在最早的问题处停下来。整段已经发出，就定位原句并从第一处问题开始反馈；不假装在发出前听到了内容。
- 指明原句或步骤 → 缺了什么条件、哪里跳了步或偷换了说法 → 怎样补证或重讲。只评价推理和证据，不夸奖、不评价人。没有可证实的错就不硬挑，改查隐藏假设、边界或跨情境应用。对材料本身有问题的地方另标，不归咎于学习者。
- 用户复述完并完成本轮审查后，**一次给恰好三个难题**：分别测试前提被拿掉、近似情境中的辨别、陌生情境的应用。题目要刁钻在推理而非歧义，先自检题意与答案；该轮不附答案或泄露关键推理。用户可以按顺序逐题作答；没作答或看过答案都不能记为独立掌握。
- 每次判题后，按表现决定下一考：卡住先找缺口，换解释或拆小后用新任务确认；连续两次同类障碍必须换表示或补先修，补完返回原目标。独立答对且能解释依据，就提高难度或换约束，不重复刷同类题。刚看过讲解的原题可用于纠正，不能算新的独立证据。题意错误或歧义导致的失败不记为学习者错因。
- 给一次针对性补救和一道不同的短题后，若仍卡住，默认记下具体障碍和待复测点，接着处理三题中下一道待答题；没有待答题就直接进入第 4、5 步。若卡点发生在三题之前的复述，简要收束复述审查，再给三道适合当前基础的难题。补救短题不抵消未处理的原题；用户明确要继续补基础时照做。收束当前题并不代表答对或达标。

## 4. 压成一页或三条规律

按用户所选格式整理本轮实际教过的内容；未指定时，关系较多用一页结构，能压缩时用恰好三条。去掉重复，保留能直接调用的判断线索：「遇到什么 → 怎么做 → 注意什么」。优先收录实际暴露的易错点。待验证的理解标出来，不把未答题或未学内容写成已会。用户可先要速查卡再回到审查。留一个无答案的提取入口；下次先闭卷作答，再翻速查。

## 5. 核对适用边界与原文

- 对要留下的核心结论，列出成立前提、会失效的情境，以及至少一个具体反例：改掉哪个前提，结果如何不同。反例用来击破过度泛化；如果只是超出适用范围，要说清楚它没有推翻原结论。
- 独立重新打开实际原文，核对影响结论的数字、单位、口径、关键引述与归属。书籍用可确认的版本和章/节/页码或段落定位；论文、标准、官方资料给可访问链接及相关表、图或章节。资料允许时主动找一手来源；搜索摘要、转述和上轮回复不能作为已复核的证据。「仅用此书」时不引入书外资料。
- 找不到、看不到或来源互相冲突时，说明具体哪一项待核对；能确认的部分先给，暂不保留无依据的精确数字或作者归属。发现错误就改正速查结论并标出变化。沿用 [原文保真规则](source-integrity.md)。
- 给一个改变关键条件的新情境，让用户判断结论还适不适用并说明理由。若第三步已有同等证据，复用证据，把该点留到下次间隔复测。不要把已解释过的反例原样当作新题，也不把当前换题算成隔时复测。后续从到期的薄弱点中挑一个短测，见 [复习与迁移](review.md)。

速查和核验可以同一轮交付，也可按用户要求先后进行。记录实际作答时，分开判断是否独立、是否正确、是否迁移或隔时；出题未答只记待办。续学断点写明知识点、五步中的哪一步、下一道待答题原文，用户未指定其他任务时先接回该题；没有待答题再选到期薄弱点。可用 [多轮行为检查](../examples/five-step-cases.md) 验收。
