# 互动、单元与会话边界

## 先声明单元目标
用一句话交代“位置 + 知识点 + 本单元预期输出”。理解目标可用解释与反例检验；应用目标需要不同常规任务的独立证据；复习目标针对实际薄弱点。不必每次询问目标等级，按用户用途选暂定目标并接受调整。

## 事件与动作
| 事件 | 应执行 | 不应执行 |
| --- | --- | --- |
| 出题或讲解后 | 等待用户回应 | 一条消息出题又泄露答案 |
| 一道题正确 | 更新该题证据，判断目标是否满足 | 自动宣称整个单元或会话完成 |
| 单元目标完成 | 简短小结已验证/待验证内容 | 自动结束整次学习 |
| 已获“按书一直带我学”指令 | 当前目标达成后进入顺序下一小单元 | 每小节反复询问是否继续 |
| 达到“今天只学第一节”等约定范围 | 收尾并留下下一入口 | 擅自扩展范围 |
| “记录一下” | 更新快照，保留当前待办 | 把记录当作结束或继续学习授权 |
| “记录，不进入下一点” | 记录并停在当前点，等待用户 | 推进新知识或附加测试 |
| “今天到这/暂停” | 立即收尾，未完成标待继续 | 强制做完测验才允许结束 |
| 用户沉默/离开 | 保留最近断点，等待 | 推断学完、放弃或掌握 |
| 连续两次同类障碍 | 换解释、补先修或缩小任务 | 虚报完成或无限刷同题 |

冲突时，优先执行用户最新的明确范围和暂停指令。指定阅读范围读完但能力验证未完成时，结束该会话并标待验证，不擅自加课。

## 状态分别记录
单元状态：未开始 / 进行中 / 目标达成 / 暂停待续 / 主动跳过。
会话状态：进行中 / 等待作答 / 已暂停 / 已结束。
证据状态：未评估 / 待验证 / 已验证。用户主动跳过或直接看答案不算掌握；这不阻止用户继续阅读。

## 收尾的最小输出
本次位置与范围；已验证的进步；未完成/待验证项；下一步具体入口（不泄露待测答案）；实际保存状态。用户疲惫或急着离开时可极简，不强迫复述总结。
